- 2026-08-12 — **Sprint 4 broad review pass: two findings fixed.** From the first pass across previously-unreviewed merged slices.
    - **`EfIdeaRepository.ListByOrganizationAsync` — escaped `LIKE` pattern with no `ESCAPE` clause.** All eight `EF.Functions.Like` calls in the org-wide all-column search used the two-argument overload. Detail and root cause recorded against the item-3 entry below, which this corrects.
    - **`Csv.Parse` rewrote CRLF inside quoted fields.** `Parse` normalised the whole document (`Replace("\r\n", "\n")`) *before* the quote state machine ran, so the CRLFs inside quoted fields were rewritten too: a Windows-authored multi-line idea description came back from an export → re-import round trip with its line endings silently changed, contradicting the type's own "Write/Parse are a lossless pair" contract. Line-ending handling moved into the state machine — outside quotes CRLF/CR/LF all still terminate a record (a CRLF pair consumes its LF so it can't open an empty one), inside quotes CR and LF are content and are preserved verbatim. Side effect: the `\r` formula trigger is now actually reachable on the way back in, so that guard is testable for the first time.
  **Verified:** clean build; full suite **561 green** (113 Domain + 189 Application + 107 Infrastructure + 152 API), up from 547. New coverage: 4 Infrastructure tests on the ideas-list search (literal `_`, bare-wildcard terms, literal `%`) and 10 API tests on CSV line-ending round trips. **Caveat recorded honestly:** the new Infrastructure tests pin the pattern-building side and document intent, but they pass with or without the `ESCAPE` clause — the InMemory provider evaluates `Like` client-side and cannot distinguish the overloads. The missing-`ESCAPE` defect is only observable against a real relational engine; that check is on Sprint 5's DoD.
- 2026-08-12 — **Profile portrait upload (Sprint 4 P1) — built and merged** (`a993102`, merged `0d3c0d5`). A user can upload a portrait that replaces the initials avatar everywhere it renders (nav rail, profile page, idea drawer, board cards), capped at 25×25 px.

    - **Layering.** An `IImageProcessor` abstraction in Application keeps the imaging dependency out of the Application layer; `SkiaSharpImageProcessor` in Infrastructure implements it. Library = **SkiaSharp 2.88.8**, user-approved 2026-08-11.

A renamed text file, an executable, or a forged/truncated header fails to decode and is rejected. Accepted formats GIF/JPEG/PNG; accepted images are downscaled to fit the box (aspect preserved, never upscaled) and re-encoded as a fresh PNG, so **no original upload bytes are persisted verbatim**.

GIF coverage now uses a real 1×1 GIF89a literal and asserts the accept-and-re-encode path; the helper asserts on null so an unencodable format fails naming the format instead of throwing an NRE.
  **Verified:** clean solution build; full suite **547 green** (113 Domain + 189 Application + 102 Infrastructure + 143 API) re-run 2026-08-12 against `fd5e287`. Includes a rejection test for disguised non-image content, satisfying that clause of the Sprint 4 DoD.

The decisions are retained below as the interview record — **the spec is authoritative if they ever disagree.** Approach: the chat is **grounded** on the org's own structured data (retrieval), and **contained** by making structured output the model's only channel — retrieval alone does not keep a model on topic.
    * **D-SCOPE** = **Idea Types + an Org-Admin-editable scope statement.** The structural boundary is "could this become an Idea of one of this org's active Idea Types?"; an Org Admin also sets a free-text narrowing statement (e.g. "business process improvement only"). No embeddings, no `pgvector`, no dependency on the Sprint 5 Postgres migration.

UDF values and tag suggestions are out of v1 scope (the resolved field set changes when Idea Type changes, which complicates the drafting loop).
  **Implementation shape implied by the above:** the per-request JSON Schema is built from the retrieval result so `idea_type_id` / `business_impact_id` are **enums of the org's real option ids** — invalid classification becomes structurally impossible rather than prompt-discouraged. The model's only user-visible text field is `next_question`; there is no free-form assistant channel. The system prompt and retrieved context are assembled **server-side** from the caller's org claim — the Client sends only `{boardId, transcript}` and never a prompt. Model is a drafting aid, never a write path.
