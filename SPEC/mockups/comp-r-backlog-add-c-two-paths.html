    Issue added

    Notes

    DECISION

    Does "From an existing idea" duplicate Promote?

    Yes, on purpose: it is the same command (the Promote use case: Effort required, optional sprint, upvote snapshot, author-or-admin authorization, same audit event), reached from the Backlog instead of from the idea. Weigh: a second door raises discoverability, but the two entry points must never drift (same refusals, same copy, same toast). The idea's own Promote stays.

    DECISION

    Dialog or drawer for New issue?

    Dialog: three fields is a quick capture and needs no surrounding context. The cost is a split vocabulary, since Edit uses the existing Issue drawer and "Add details" is a dialog expanding toward something the drawer already is. Alternative: open the drawer in create mode and drop the dialog.

    DECISION

    Mobile at 390px

    Both dialogs become full-height sheets with a sticky footer (Cancel and the primary action share the row). The Add button goes full width, its menu spans the viewport, the table collapses to labelled cards. The picker list stops scrolling on its own so the sheet scrolls once. Resize to 390px to check.

    DECISION

    Where a new issue lands

    The Backlog sorts by votes, so a New issue (0 votes) lands last, and one added to a sprint is not in this list at all (toast: "Issue added to Sprint 14"). A promoted idea lands by its upvote count (state 7). Focus returns to the Add button; the new row is highlighted and carries a "Just added" chip, so colour is never the only cue.

    ROLES

    Who sees what

    Read Only: Add and the row Edit actions are disabled and the reason is printed beside the button, not only in a tooltip. User: the picker lists only ideas they authored (promotion is author or admin). Org Admin: every eligible idea. Use "Viewing the picker as" above.

    A11Y

    Menu and dialog behaviour

    • Add is a menu button: aria-haspopup, aria-expanded, Enter/Space/Down opens, arrows move, Esc closes and returns focus to Add.
    • Dialogs: role=dialog, aria-modal, labelled by the heading. Focus moves to Title (or Search in the picker), Tab and Shift+Tab wrap inside, the page behind is inert, Esc and Cancel close and return focus to Add.
    • Errors: a summary with links plus a message under each field, aria-invalid and aria-describedby. Success is announced by the status toast.

    Trade-offs of this approach. (1) Two doors to one command: discoverable from one place, but the Backlog and the idea page must stay in lockstep. (2) The Add menu hides both paths one click deep; a single-purpose button would make New issue one click faster for the common case. (3) The picker adds a second dense surface (search, filter, select, then Effort and Sprint), heavier than promoting from the idea you are already reading.
