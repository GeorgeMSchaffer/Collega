Notes

Behaviour

  • Enter in Title or either select submits. Escape closes More fields first if open, otherwise clears the row; a further Escape leaves the row. Add is always clickable, because a dead button cannot say why. With nothing typed it is an outline button; once Title and Effort are both set it turns primary.
  • Errors appear beside the control they belong to (“Enter a title.”, “Choose an effort.”), the field gets aria-invalid, and focus goes to the first invalid one.
  • On success the row is inserted at the top of the table and highlighted. Title and Effort clear, Sprint keeps its value (people usually batch into one sprint), focus returns to Title, a polite live region announces the result, and the toast reads “Issue added”.
  • Edit: a row’s Edit button opens the existing Issue drawer in edit mode. Double-clicking a title renames it in place (Enter saves, Escape cancels); this is optional and works in any state with rows.
  • Read Only members get a disabled bar in place of the row, with the reason as visible text: “Read Only members cannot add issues.”

Decisions to weigh

  • Mobile at 390px. The row stacks: Title full width, Effort and Sprint side by side, Add full width at 44px height. Table rows become cards (key and assignee on the first line, then title, effort, sprint, Edit). Open question: should More fields hand off to the drawer on small screens, since a long form inside a list row scrolls awkwardly?
  • Accidental adds. Enter submits, so a stray Enter after a half-typed title adds a half-typed issue. Mitigations: Effort is required (a deliberate second choice), the new row is highlighted, and the toast should carry an Undo link (not drawn). Without Undo this is the main risk of the approach.
  • Defaults hiding required-by-org fields. The quick path sends only the API minimum, with Idea type and Business impact defaulted to the organization’s first active values. The defaults are printed under the row so they are not silent. If an organization requires something else (a custom field, say), the quick row cannot satisfy it. Proposed handling: the row opens More fields automatically with the missing field flagged, rather than failing.
  • A sprint other than Backlog. An issue added to Sprint 14 does not belong in the Backlog list, so no row appears; the toast says where it went. Alternative: drop the Sprint select from the quick row and leave sprint planning to the sprint screen.
  • Keyboard and desktop first. The pattern shines for batches typed from a list; it is weaker for someone adding one issue with detail.
