Pulling existing items onto a board, and ideas with no board

Slice 182, a throwaway comp for review. It draws SPEC/20-feature-board-pull-in.md in comp R's look (Graphite by default, the theme picker above). Nothing here is built; the UI waits on your approval. Sample data is Acme Robotics. The selectors, tabs and step are live so you can feel them; saving does nothing.

A Board drawer, create, as an Org Admin

Draws rules 9, 10, 13, 14, 17 and the UI section. The step sits after the existing fields and is collapsed by default; collapsed, it carries a one-line summary. Each row says where the item will land (rule 13), and the footer repeats the rule once.

Decision where the spec was silent The Create button names the count ("Create board and add 3 items") so the pull is never a surprise. A Backlog Issue row also shows its task count, since "tasks kept" is the reason an admin would choose it.

B Board drawer, create, as a plain User

Draws rule 11 (a User pulls only Discovery ideas they authored, from the pool or from other boards; Backlog Issues are Org Admin only). There is no Backlog Issues tab and the list is already narrowed to Noah's own ideas, with the one-line note.

C Board drawer, edit of a live board, as an Org Admin

Draws rules 9 and 13 on an existing board ("Product Roadmap"). Its own ideas are never listed (Roadmap's ideas are missing from the tabs; counts are lower than in A). The Planned lane is being removed in the same save, so the interplay note shows and the "Lands in" hints are computed against the lanes after the save (New, Under Review, Done): an item in Planned now lands in the first lane.

Open question The lane-removal guard asks where the ideas in Planned go; a pulled item that was in Planned lands in New by rule 13, not in that chosen lane. The comp says so in the hint; confirm that is intended.

D Refusal states

Draws rules 12, 16, 17 and 9 (archived). The refusal is keyed to the step: the alert sits at the top of the step, the step header carries a "Needs attention" flag, the refused items are marked in the selected list and in the rows with text (never colour alone), and a line states that nothing was saved. The alert is role="alert". The over-cap state disables the save with a visible reason; the server's 400 on pullItemIds is still the authority.

E Idea form: Board select with "No board"

Draws rules 3 and 4 and the UI section. Board becomes a select whose first choice is "No board". Opened from a board it is preselected to that board; opened from the Ideas list it shows "No board" (the empty value). The helper text appears while "No board" is chosen. Only the Board field is new; other fields are drawn short because they are unchanged (see idea-form.tsx).

Decision There is no Status field in either state: the status of a pool idea is fixed by rule 3 (see frame H), and on a board the existing behaviour is unchanged.

F Ideas list and idea drawer: no board, and Remove from board

Draws rules 5, 6, 7 and the UI section. The Board filter gains "No board" (with a count); the Board column shows a dashed "No board" chip. "Remove from board" is a row action for the author or an Org Admin and asks for a confirm that says what stays. An Issue cannot be detached (409), so its row shows the action disabled with the reason. On an archived board only an Org Admin may detach; a User sees it disabled with a reason.

Decision An idea already in the pool offers no Remove from board (the route is idempotent, but a button that does nothing is noise). The drawer's board line therefore reads "No board" with a short pointer instead of the action.

H Open for review

The two details the spec still marks (proposed), then questions that came up while drawing. Everything else in the comp follows answered rules.

PROPOSED · RULE 3

Status of an idea created with no board

Default: the organization's first active status in sort order (the status the leftmost lane of a new board would carry). If there is no active status, creation is refused with a 400 on statusId.

Consequence you will see in the comp: the idea form has no Status field for a pool idea, and "Lands in" hints treat a new pool idea as New.

PROPOSED · RULE 13

In-lane order of pulled items

Default: appended after the cards already in the lane, oldest first.

Alternative: newest first, or keep the order they had on their previous board. The footer line in frames A to C states the default.

NEW · FRAME G

The Needs a board tile at zero

Default: hidden at 0.

Alternative: shown with 0 as a quiet confirmation that nothing is waiting.

NEW · FRAME F

Remove from board on a pool idea

Default: not offered (nothing to remove). The drawer shows "No board" and a pointer.

The route stays idempotent either way.

NEW · FRAME C

Pulled item from a removed lane

Default: rule 13 places it by the lanes as they stand after the save, so an item whose status was the removed lane lands in the first lane, not in the lane chosen for the board's own ideas.

Confirm that is what you want, or say the chosen lane should apply.

NEW · FRAME A

Pulled ideas whose status changes

Default: the row hint says "first lane" with the status it will take, and the audit writes IdeaStatusChanged. No further confirmation.

Alternative: ask for a confirm when more than a few statuses will change.
