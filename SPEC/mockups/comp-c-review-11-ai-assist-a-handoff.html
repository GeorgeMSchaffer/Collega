Direction A — Conversation → Handoff

Keeps the shape the product already has: a centered chat modal, then the create modal. The assistant's work becomes visible at the handoff — you talk, then you see the filled form. This is the smaller change and the smaller risk.

What it settles

  • Suggestion indicator: a teal Suggested chip beside the label, plus a 3px left border and tinted field. Teal is used because indigo already means "active/selected" everywhere in Comp C — a suggestion is neither.
  • Out-of-scope: the offending turn renders ghosted and struck through, then disappears on the next render — a visible confirmation that it was dropped (rule 8) rather than silently swallowed. The redirect is a system note, not an assistant bubble, so refusals never look like conversation.
  • Pending: a three-dot bubble in the assistant's own slot; composer disabled; the turn is cancellable (rule 33). Skip & fill manually stays enabled — rule 3 says it is never gated on a model call.
  • Failed: a system note that keeps the user's text, offers Retry, and states plainly that nothing is lost. The footer reads "running in basic mode" once degraded (rule 32).
  • Scope statement: its own Settings page with a live counter, the active Idea Types shown as the floor, and the fixed redirect string previewed.

Why the off-topic turn is shown at all

Rule 8 drops the turn from the transcript. The literal reading is to render nothing — but then a user who typed something watches their message vanish with no explanation, which reads as a bug. Ghosting it for one beat says "received, not kept", which is the honest description of what the server did.

Decision needed — is the strike-through worth it?

The alternative is to never render the off-topic message at all. Cleaner, but silently discards typed input. This comp proposes ghost-then-drop; say the word if you'd rather it never appear.

Trade-offs vs Direction B

  • For: reuses CreateModalShell unchanged; no new surface; smallest diff; works at 768px without a rethink.
  • Against: classification is invisible until the handoff, so a user cannot tell the assistant mis-typed their idea until the form appears. The "big reveal" is also where all the correction work lands.
  • Against: nothing on screen teaches the user that the chat is doing anything beyond talking.
Open question — where does the scope statement live?

Drawn as a dedicated Settings page. Alternative: a section in the Organization detail drawer. The drawer keeps surface count down but is already long; a page is easier to link to from the assistant itself.
