Direction C — Draft Strip

11A's flow exactly — one 720px surface at a time, chat then create modal, CreateModalShell unchanged — with a slim read-only strip between the transcript and the composer. The strip shows only what the assistant has classified: Idea Type, Business Impact, Priority. Title and description are summarised, never rendered in full.

Why read-only is the point

The expensive part of 11B isn't the second pane — it's that an editable draft needs per-field "suggested vs. user-edited" state, and a rule for what happens when a later turn wants to overwrite something you changed. Make the strip read-only and that entire problem disappears: it is a projection of the last response, nothing more. You still see the assistant classifying in real time, which is the actual benefit 11B was buying.

What it settles

  • Suggestion indicator: identical to 11A on the form — teal chip, tinted field, 3px left border. The strip uses the same teal so the two surfaces read as one idea.
  • Nothing is a surprise at handoff. The form's banner says so explicitly. 11A's weakest point was that all correction work landed at the reveal; here you have had three turns of warning.
  • Out-of-scope: the strip is annotated unchanged — the same "your off-topic turn moved nothing" proof 11B gets from its panel, in one word.
  • Pending: the strip dims but stays readable, and Skip & fill manually stays enabled (rule 3).
  • Not-yet-classified is rendered explicitly ("Priority not set yet") rather than omitted, so the user can tell the difference between "the assistant chose nothing" and "the assistant hasn't got there".

Recommendation

C, unless you specifically want to edit classification mid-conversation. It takes A's cost and risk profile and removes A's one real weakness — that the user learns nothing until the reveal. B remains the right answer only if correcting the Idea Type while talking turns out to matter, and that is a question real usage answers better than a comp.
